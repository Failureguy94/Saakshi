# Saakshi Scientific Forensic Validation Plan

## 1. Overview

In accordance with ASTM E3016 (Standard Guide for Establishing Confidence in Digital Forensics
Methods) and SWGDE (Scientific Working Group on Digital Evidence) standards, Saakshi validation
is conducted in two tiers:

1. **Synthetic-only tier** — automated, reproducible, fully offline.  All results in this tier
   come exclusively from data generated by `scripts/make_synthetic_dvr.py` and similar synthetic
   generators.  These results **MUST NOT** be cited as real-device performance in any submission,
   court report, or publication.

2. **Lab-hardware tier** (PLANNED — not yet executed) — requires certified write-blocked hardware,
   at least 5 distinct DVR/NVR units per vendor, and independent re-execution by a second analyst.

> **⚠ CRITICAL DISCLAIMER**
> Every JSON report in `docs/validation/synthetic_validation_*.json` is produced from
> **SYNTHETIC DATA ONLY**.  The footage is algorithmically generated; it is not evidence from any
> real device.  Carver recall and precision figures from synthetic tests measure how well the
> algorithm recovers its own known-output streams — they cannot substitute for controlled
> experiments on real surveillance hardware.

## 2. Synthetic Validation — Methodology

### 2.1 Disk Image Generation (`scripts/make_synthetic_dvr.py`)

| Parameter | Description |
|---|---|
| `--channels` | 2–4 simulated camera channels |
| `--clips-per-channel` | Clips per channel (default: 4) |
| `--clip-duration` | Seconds per clip |
| `--overwrite-factor` | Fraction of clips partially overwritten (ring-buffer simulation) |
| `--delete-fraction` | Fraction of index entries zeroed (simulates DVR deletion) |
| `--damage-fraction` | Fraction of clips with a corrupted GOP header byte |
| `--seed` | Deterministic seed for reproducibility |

The generator writes a `ground_truth.json` containing exact byte offsets, true timestamps,
channel IDs, codec type, and damage flags for every clip.

### 2.2 Carving & Repair Pipeline

```
make_synthetic_dvr.py ──→ synthetic_dvr.img + ground_truth.json
      │
      ▼
PythonAnnexBCarver.carve_stream()   ←── nal_carver.py
      │
      ▼
group_into_gops()                   ←── nal_carver.py (GOP grouping + SegmentRecord)
      │
      ▼
repair_gops()                       ←── gop_repair.py (SPS/PPS donor borrowing)
      │
      ▼
validate_recovery.py ──→ precision / recall / byte-rate / JSON report
```

### 2.3 Match Criterion

A recovered segment is counted as a **hit** for a ground-truth clip if the byte-overlap ratio
meets or exceeds 0.50 (50 %).  Clips rated 90 %+ overlap are counted as **exact** matches;
50–90 % as **partial** matches.

Overwritten clips are excluded from the evaluable set (their data is physically gone by design).

### 2.4 Metrics

| Metric | Formula |
|---|---|
| Precision | TP / (TP + FP), where TP = exact + partial matches |
| Recall | TP / evaluable_clips |
| F1 | 2 × P × R / (P + R) |
| Byte recovery rate | Fraction of evaluable ground-truth bytes covered by any recovered segment |

## 3. Test Suites

### 3.1 Hashing Validation
- Verification against NIST Known Hash Datasets (NSRL) and zero-length / edge-case files.
- Streaming chunk equivalence check (chunked vs monolithic).
- CLI `saakshi acquire --verify-sha256` round-trip.

### 3.2 Annex-B NAL Carver Validation
- Synthetic images with deterministically positioned H.264 / H.265 NAL units at odd byte offsets.
- GOP grouping: SPS/PPS/IDR/P-frame detection and codec classification.
- Streaming chunk-boundary split resistance (8-byte overlap window).

### 3.3 GOP Repair Validation
- Segments missing SPS/PPS receive correct parameter sets from nearest valid neighbour.
- Repaired segments are marked `repaired=True` and confidence is reduced by ×0.7.
- No mutation of the input segment list (deep copy guarantee).

### 3.4 Recovery Export Validation
- ffmpeg `-c copy` (no re-encode) call verified via mock.
- SHA-256 of exported .mp4 matches manual computation.
- Custody log entries written for every successful export.
- Clean `ExportError` raised when ffmpeg is absent.

### 3.5 Merkle Tree & Custody Chain
- Tamper detection tests simulating single-bit mutations in historical custody records.
- Inclusion proofs across arbitrary power-of-two and odd leaf sizes.

### 3.6 End-to-End Pipeline (Synthetic)
- `test_synthetic_dvr_pipeline.py::TestFullPipeline` runs the complete
  generate → carve → repair → match pipeline in a single pytest session.
- Recall > 0 % is the acceptance gate (proves the carver recovers at least one clip).

## 5. Result Files

All synthetic validation JSON reports are stored under `docs/validation/` with the naming
convention `synthetic_validation_<YYYYMMDDTHHMMSSZ>.json`.  Each report embeds a
`"warning"` field that reads:

> *"SYNTHETIC DATA ONLY. Results must NOT be presented as real-device performance."*

Absence of the `"warning"` field in a result file, or a report claiming real-device accuracy
based solely on these files, constitutes a scientific integrity violation.
